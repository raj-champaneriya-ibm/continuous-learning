Acme Fibre · Engineering ADR-001
Presenter: Forward Deployed Engineer Duration: 5 Minutes
01 · Executive Summary

How Acme Fibre Should Automate Support Emails

A first-principles architectural evaluation: Rules vs. Single LLM Call vs. Autonomous Agent.

🏢 Operating Reality

• 1,200 emails / day in Pune
• Asynchronous SLA (minutes are acceptable)
• Brand trust is the non-negotiable metric

🛡️ Core Mandates

• 0 Policy Violations (OTPs, passwords)
• Never bypass escalation when human needed
• Compute & unit cost must scale locally

🎯 The Recommendation

Build a Workflow, Not an Agent:
Option B with a pre-LLM safety router and post-LLM deterministic policy check.

Bottom Line: Autonomous multi-turn agents are 20× slower, 7× more expensive, and fail safety policies. Deterministic workflows deliver higher safety at predictable SLAs.
02 · Architectural Options

Three Competing Architectural Paradigms

Tested against an 84-case benchmark (40 requiring human escalation) with strict automated policy grading.

Option A Deterministic
Rules & Templates

Keyword regex rules classify customer intent and populate rigid string templates without an LLM.

✅ Zero latency & cost
❌ Zero nuance, misses 100% of escalations
Option B (Core) Recommended Base
Single LLM Call + Context

One model call injected with structured customer card and relevant knowledge base articles.

✅ High factual accuracy (74%)
⚠️ Requires front-end router for safety
Option C Autonomous Loop
Multi-Turn Agent + Tools

Autonomous ReAct loop with up to 6 tool calls to search KB, look up accounts, and decide actions.

❌ p95: 213s, breaks policy in 8 replies
❌ 35 hours compute / day on 1 machine
03 · Empirical Findings

The Scoreboard: Overlapping Pass Rates, Divergent Safety

Evidence gathered across 84 runs with statistical uncertainty (±2 Standard Errors).

Option Pass Rate (± 2 SE) Safe Rate (± 2 SE) Missed Escalations Median Latency p95 Latency Cost / 1k Emails
A · Rules 19% ± 9% 52% ± 11% 40 of 40 (100%) 0.0 s 0.0 s ₹0.00
B · Single Call 29% ± 10% 54% ± 11% 38 of 40 (95%) 4.3 s 6.2 s ₹1.30
C · Agent Loop 20% ± 9% 71% ± 10% 17 of 40 (42%) 104.2 s 213.8 s ₹8.70
Key Insight 1: Pass Rate is Indistinguishable

With overlapping error bars, no architecture wins on accuracy alone. Safety (preventing policy leaks & missed human handoffs) must determine the ship decision.

Key Insight 2: Agent Compute Bottleneck

At 104s median and 213s p95, 1,200 daily emails require ~35 hours of active compute per day on local hardware. The agent creates immediate queue starvation.

04 · Error Analysis

Why They Failed: Dissecting the Bottlenecks

Failure mode breakdown from Day 10 error analysis across 84 runs.

🚫 A's Failure Mode

Blind to Context:
Cannot detect sentiment, frustration, or subtle escalation cues.

Result: Failed 40 out of 40 human escalation cases by attempting to template answers.

⚠️ B's Failure Mode

Over-Helpful Answering:
High factual accuracy (74%) but answers emails that legally require humans.

Caveat: Uses oracle context (pre-selected articles). Needs a dedicated front router.

💥 C's Failure Mode

Policy Breaches & Search Lag:
Breached strict policies in 8 replies (e.g. promising unapproved refunds).

Tool search dropped facts to 36% (vs. B's 74%) while inflating latency 25×.

📌 Takeaway: Do not use an LLM loop where deterministic code suffices. Move escalation and policy verification out of the prompt and into software logic.
05 · Target Architecture

The Recommended Topology: Guarded Workflow

Encapsulating safety and policy checks in deterministic code rather than probabilistic prompts.

06 · Risk & Governance

Go-Live Gates & Phased Rollout

Strict quantitative criteria before disabling human review on production traffic.

Gate 1 · Zero Tolerance
0
Policy Violations

Zero OTP leaks, zero unapproved refund promises, zero fabricated discount commitments.

Gate 2 · Safety Recall
≤ 2 / 40
Missed Escalations

At least 95% of emails requiring human intervention are correctly diverted to the queue.

Gate 3 · Quality Floor
> 19%
Pass Rate Lower Bound

Statistical confidence interval lower bound must strictly exceed Option A's baseline.

🚀 Rollout Strategy: Shadow Mode First

Phase 1 (Shadow Mode): The system drafts all 1,200 replies. Human agents see pre-populated drafts in Zendesk/Freshdesk and one-click approve or edit. Reduces handle time by 50% without risk.
Phase 2 (Automated Egress): Unreviewed sending is enabled exclusively for high-confidence intents that clear all 3 gates.

07 · Falsification Criteria

What Would Change My Mind?

Explicit empirical triggers that would alter this architectural recommendation.

Trigger 1 · Safety Limit
Router Misses > 2 of 40

If the safety router cannot achieve ≥95% escalation recall:

Action: Abort automated drafting completely. Revert to Option A regex templates + 100% human triage.

Trigger 2 · Agent Breakthrough
Frontier Model Meets SLA

If Option C on a hosted frontier model achieves 0 policy breaks with p95 < 60s at viable cost:

Action: Adopt Option C. The agent will have earned its architectural complexity.

Trigger 3 · Retrieval Decay
Search Drops Facts > 10%

If replacing oracle context with real search degrades B's factual accuracy by >10 points:

Action: Halt model deployment. Shift engineering entirely to retrieval indexing (Project 2).

08 · Engineering Roadmap

Roadmap & Open Questions (Projects 2 – 6)

Systematically de-risking the remaining uncertainties before production deployment.

🔍 Project 2 · Real-World Retrieval (RAG)

• Measure factual retention when searching KB articles dynamically vs. oracle context.
• Quantify chunking and ranking impact on synthesis accuracy.

🧠 Project 3 · Learned Safety Classifier

• Benchmark a small local embedding/transformer classifier vs. prompt routing.
• Objective: Reduce safety router latency from 500ms to <20ms.

🔬 Projects 4 & 5 · Error Attribution

• Isolate errors stemming from model size vs. prompt phrasing vs. grader false alarms.
• Harden mutation tests to prevent false negatives in policy validation.

⚡ Project 6 · Frontier Model & Real Traffic

• Re-evaluate Workflow B vs. Agent C on hosted frontier LLMs.
• Final production validation on anonymized live Acme email stream.
