Gradient boosting is one of the most-used tools in machine learning. The idea fits in one sentence: build lots of tiny trees, each one fixing the mistakes of the trees before it. This guide shows you that idea in pictures, then lets you run it with your own hands.

Each tree on its own is a crude staircase. Added together, they draw the shape of the data.

Ravi's milk problem

Chapter 2

One small tree can only say a few numbers

A decision tree is a flowchart of yes/no questions. Each question splits the days into two groups. For every group, the tree predicts the group's average.

The smallest possible tree asks one question. It's called a stump. Here is the best stump for our six days:

Only two possible answers. Every day under 24.5 °C gets 89 cups, whether it's 15 °C or 24 °C.

How did it pick 24.5 °C?

It tried every cut between neighbouring temperatures. For each cut it measured the squared error: how far each day is from its group's average, squared and added up. The cut with the smallest error wins.

Shorter bar = the two groups are more alike inside. 24.5 °C just beats 29 °C.

Think about it

A stump is a blunt tool. Why not grow a deep tree with enough questions to hit every single day exactly? Write down your guess. Chapter 6 answers it.

Chapter 3

The big idea: fix the mistakes, one small tree at a time

A golfer doesn't sink a long hole in one swing. The first shot gets close. Every shot after that only has to cover the distance that's left.

Each new tree only has to learn what's still missing.

Boosting is exactly that, written as a loop:

  1. Start with a simple guess for every day: the average.
  2. Measure what's left. For each day, actual − predicted. These leftovers are the residuals.
  3. Train a small tree to predict those residuals.
  4. Add a fraction of that tree's answer to the model. Go back to step 2.
new prediction = old prediction + learning rate × tree's answer

The fraction is called the learning rate. Small learning rate, small careful steps. Here's the loop running on Ravi's whole month, using stumps:

1 stump is a single step. 50 stumps, added up, trace the curve.

Chapter 5

Why is it called gradient boosting?

Picture the error for one day (the 15 °C day, which sold 98 cups) as a bowl. The bottom of the bowl is the perfect prediction. Our first guess, 67, sits up on the side.

The blue ball is our guess. The way downhill points straight at the residual.

For squared error, the loss for one day is ½ (actual − prediction)². Its slope (the gradient) is −(actual − prediction). The downhill direction is the negative of the slope:

downhill direction = actual − prediction = the residual

So "train a tree on the residuals" secretly means "take a step downhill on the error". That's gradient descent, done with trees. Each tree is one step.

Swap in a different loss and the loop stays the same. Only what the trees chase changes. People call these pseudo-residuals:

LossEach tree chases…Good for
Squared erroractual − predictedOrdinary numbers
Absolute errorjust the sign: +1 or −1Data with outliers
Log-lossactual (0 or 1) − predicted probabilityYes/no questions
Chapter 6

There are no silly questions

QWhy start with the average?A

Of all single numbers, the average has the smallest squared error. Any start would work, but the average saves the first few trees some effort.

QWhy add only a fraction of each tree?A

Each tree is fitted to a handful of noisy residuals, so its advice is rough. Taking a fraction means no single tree can push the model too far. Many small steps average out the noise. The price is that you need more trees.

QSo why not one deep tree that fits every day exactly?A

It would fit the noise too: the random ups and downs that won't repeat tomorrow. Its predictions on new days would be poor. Boosting adds detail slowly, and you can stop as soon as error on fresh data stops improving.

QWhy are the trees so small?A

Each tree only has to point roughly the right way. Small trees are called weak learners: cheap to train and hard to overfit. Hundreds of them added together can draw almost any shape.

QReal data has many features. What changes?A

At every split the tree tries every feature and every cut, then picks the one that most reduces error on the residuals. A depth-3 tree can then capture combinations like "hot and weekend". We used one feature so you could see the whole picture.

QCan it answer yes/no questions (classification)?A

Yes. The model adds up a score, and a sigmoid turns the score into a probability. The residual becomes actual (0 or 1) minus predicted probability. Same loop.

QWhere do XGBoost, LightGBM and CatBoost fit in?A

They are fast, well-tested versions of this same loop. On top, they add penalties that keep leaf values small, use the curvature of the loss to choose leaf values, bucket features into histograms for speed, and handle missing values. The core idea is the one on this page.

Think about it

Press Overeager. In the error chart, the blue line keeps falling toward zero, but the red line bottoms out early and then climbs. What is the model doing after that low point?

Show answer

It's overfitting: memorizing the random wiggles of the 30 training days. Training error keeps improving while error on new days gets worse. Look at the prediction curve, too. It zig-zags to touch individual dots.

Careful!

More trees is not always better. A random forest barely suffers from extra trees, but a boosted model eventually starts memorizing. Always keep a validation set and use early stopping: keep adding trees only while validation error improves.

Learning rate and number of trees trade off. Halve the learning rate and you'll need roughly twice the trees. Small rates with many trees usually generalize best.

Chapter 8

Tea-break debate: Random Forest vs Boosting

Tonight's guests, both made of trees.

Forest

I grow hundreds of deep trees, each on a random sample of the data, all at the same time. Then they vote.

Booster

I grow small trees one after another. Each one studies the mistakes of everything before it.

Forest

So you're stuck in a queue. I can train all my trees in parallel.

Booster

My libraries parallelize the work inside each tree. And on tables of data I'm usually the more accurate one.

Forest

You need tuning, though. Learning rate, depth, number of trees. My defaults just work.

Booster

Fair. Leave me running too long and I start memorizing noise. That's why I use early stopping.

Forest

I average away randomness. My trees are deep and wild, and the crowd calms them down.

Booster

And I chip away at bias. My trees are simple, and the sequence makes them sharp. Different jobs.

Forest

The whole algorithm, from scratch

Ten lines of real code. It reproduces the six-day example exactly (run it with n_trees=3, lr=0.5, depth=1).

import numpy as np
from sklearn.tree import DecisionTreeRegressor

def boost(X, y, n_trees=100, lr=0.1, depth=2):
    f0 = y.mean()                     # step 1: the plain average
    pred = np.full(len(y), f0)
    trees = []
    for _ in range(n_trees):
        residual = y - pred           # step 2: what's still wrong?
        tree = DecisionTreeRegressor(max_depth=depth).fit(X, residual)
        pred += lr * tree.predict(X)  # steps 3-4: nudge, don't jump
        trees.append(tree)
    return f0, trees

def predict(f0, trees, X, lr=0.1):
    return f0 + lr * sum(t.predict(X) for t in trees)

Chapter 10

The whole thing on one card

F₀ = average(y)  start simple
for m = 1 … M:
  rᵢ = yᵢ − Fₘ₋₁(xᵢ)  what's left
  hₘ = small tree fitted to (xᵢ, rᵢ)
  Fₘ = Fₘ₋₁ + η · hₘ  η = learning rate
predict(x) = F₀ + η · (h₁(x) + … + h_M(x))

Key takeaways

  • A boosted model is a starting guess plus a sum of many small trees.
  • Trees are built one after another. Each is trained on the residuals the model is still getting wrong.
  • Residuals are the downhill direction of the loss. That's where "gradient" comes from. Other losses give other pseudo-residuals.
  • The learning rate shrinks each tree's say. Smaller rates need more trees but usually generalize better.
  • Trees stay small (stumps up to depth 6). They're weak alone and strong together.
  • Boosting can overfit. Watch validation error and use early stopping.
